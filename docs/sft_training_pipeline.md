# SFT 训练管线:从词表种子到可接入模型(stream-reliability-push 07 叙事文档)

> 位置:`services/engine-py/scripts/training/`(980 行,零新增依赖)。
> 一句话:**模型只学语义理解,输出 SemQL** —— 不让小模型写 SQL,不让它背答案,
> 只把「口语 → 结构化查询意图」这一步蒸馏进模型,其余交给既有确定性管线。

## 1. 这条管线解决什么问题

Data Agent 的意图层是 L3 兜底:规则(L0)/小分类头(metric_head)/范例回放(L2)
全部未命中时,才调一次大模型做意图解析。问题:每次兜底都是一次在线 LLM 调用
(成本 + 延迟 + 供应商波动)。SFT 管线把这一步**离线蒸馏成一个小模型**:
`AI_INTENT_L3_MODEL` 指向训练产物目录,线上同一代码路径直发本地推理
(`_sft_generate`,同步推理经 `asyncio.to_thread` 下放,事件循环不阻塞)。

## 2. 五步闭环(每步一个可独立讲的设计决策)

```
seed_from_registry.py   ① 词表 → 弱标注种子(39 指标 × aliases/synonyms/sampleQueries)
        │
prelabel.py             ② LLM 第二意见:管线意图是第一意见,分歧/低置信 → need_review
        │
(人工只裁 need_review 部分)
        │
sft_dataset.py          ③ 去重 → 评测句近邻过滤(cos≥0.90 防泄漏)→ 分层切分
        │
sft_train.py            ④ QLoRA SFT(transformers + peft + trl 标准栈)
        │
evaluate.py             ⑤ heldout 复检 + 新数据复检 → markdown 报告 → 达标才接入
```

- **① 种子零标注成本**:指标语义注册表(39 指标,aliases/synonyms/sampleQueries)
  本身就是弱标注金矿 —— 词表程序化展开即得种子对,冷启动零人工。
- **② LLM 只当第二意见**:第一意见永远是确定性管线的意图;LLM 分歧或低置信才标
  `need_review` —— 人工标注预算只花在模型拿不准的 5% 上,不 给全量句子买单。
- **③ 防泄漏是评测的生命线**:评测句若与训练句余弦 ≥0.90 同义,分数就是背题;
  切分前按嵌入近邻过滤,heldout 才是真 heldout。
- **④ QLoRA 免费额度可跑**:标准栈(trl)比魔改栈时长多一半,但在免费计算额度内
  —— 换取全社区可复现的依赖组合,不发明私有训练轮子。
- **⑤ 接入有门槛**:heldout 之外再拿一份新数据复检,报告达标才允许
  `AI_INTENT_L3_MODEL` 指向新目录;失败就留在离线,线上零感知。

## 3. 与 metric_head 的关系(两条蒸馏路线,一个评测纪律)

- metric_head(已上线):bge 向量 + torch 线性头,CPU 分钟级,闭集分类;
- SFT(本管线):生成式,输出 SemQL(结构化查询语言中间形),覆盖组合意图;
- 共同点:**训练产物必须过同一套离线评测纪律**,heldout 分数说话,严禁
  「训练了就接入」。

## 4. 面试追问防线

- 「为什么不直接微调大模型端到端?」→ 端到端 = 把 SQL 生成也交给小模型,
  错数不可发现;SemQL 中间形让模型只做语义理解,SQL 仍由确定性模板拼装,
  错误可归因(ADR-0010 分层信任同一哲学:LLM 永不在无守卫下产 SQL)。
- 「数据哪来?」→ ① 词表弱标注种子(零人工)② 线上水龙头导出
  (export_intent_data,2026-09-17 起自动积累)③ LLM 预标 + 人工裁 need_review。
- 「怎么知道没过拟合?」→ ③ 的近邻防泄漏 + ⑤ 的双重复检;防泄漏失守的分数
  是背题不是泛化。
- 「线上怎么回滚?」→ env 指向切换,旧目录保留;接入门槛没过就在离线,线上
  从未感知。
