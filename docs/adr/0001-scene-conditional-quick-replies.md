# ADR-0001: 聊天快捷回复按场景动态生成(引擎意图映射驱动)

- 日期: 2026-09-12
- 状态: 已实现(设计 grill-with-docs 两轮定案,双轴 code-review 修正后落地)
- 关联: CHANGELOG 2.6.8(商户货架无销量列,严禁合成假热度)、2.6.12(排行卡消歧组)、2.6.13(加购序数越界诚实反问)

## 背景

每轮**纯文本**回复末尾固定追加同一组快捷按钮「查询物流进度 / 申请退款服务 / 上传商品瑕疵照片 / 呼叫人工客服」(`card_synthesizer.py` 的 quick_replies 卡),不看对话场景;一旦该轮有域卡片(推荐/购物车/退款卡等)整行直接不出现(`run_agent.py` 的 `existing_cards if existing_cards else synthesized` short-circuit)。产品要求:退款场景提供「查询最近的订单 / 查询未发货的订单」;商品场景提供品类快捷入口。

## 事实基础(2026-09-12 代码查证)

1. 渠道已存在,无协议改动:quick_replies 卡由引擎合成,前端 `QuickReplies.tsx` 渲染,点击 = `send_message` 把按钮文本当用户消息重发。
2. `listUserOrders` 真实存在但**零参数**——「查询最近的订单」点击即可用,「查询未发货」全仓无任何发货状态过滤能力。
3. 照片上传是真实链路(上传接口 → 多模态瑕疵识别 → damage_assessment 卡),缺口仅是凭证不落售后工单(`apply_after_sale` 无凭证字段)。
4. 商户货架 6 个真实品类(户外机能/潮流T恤/下装裤类/潮流鞋靴/背包收纳/露营装备),品类过滤端到端已通;**无衬衫**。商户货架无销量列(2.6.8 铁律),`queryProductRanking` 因 manager_id 过滤恒诚实空(items=0)——「卖得好的商品」当前无法诚实兑现。

## 决策(用户逐项裁决「按照推荐」)

1. **Q1 场景判定按本轮已分类意图映射**:意图在卡合成时已在 state 中,零新增状态;按对话阶段/缺槽状态细化留给二期。
2. **Q2 退款场景组** = 查询最近的订单 / 查询未发货的订单 / 上传商品瑕疵照片 / 呼叫人工客服。「申请退款服务」在场景内撤下(用户已在退款流程中);**未发货过滤能力本轮补齐**。
3. **Q3 品类 chips 按真货架动态生成**(`get_shelf_overview` 的 ON_SALE 品类,非写死、非编造),点击走导购浏览;文案严禁「热销/卖得好/爆款」,待真销量数据到位后二期再升级文案。
4. **Q4 short-circuit 改追加**:域卡片轮也挂场景 chips——品类按钮在推荐轮恰恰最有用;仅在场景相关时挂,数量上限 6,控制拥挤。
5. **Q5 兜底通用组**(Round 2)= 查询我的订单 / 逛逛商城 / 申请退款 / 呼叫人工客服。旧「查询物流进度」并入订单查询——同一意图同一出口,订单回复自带物流/时间线;照片按钮不进通用组(闲聊场景无上下文)。
6. **Q6 场景→按钮组映射表放卡合成器内部**(Round 2):键为意图 id,呈现层自有,意图注册表零改动(promptfoo 意图基线零扰动)。

## 实现要点

- `CardSynthesizer.synthesize_cards` 收编基座裁决(域卡片优先)+ 场景组追加;`fetch_shelf_categories(intents, thread_id)` 购物轮实查、非购物轮零查库、失败诚实空。
- `run_agent.py` 与 `temporal/activities.py`(双模运行引擎另一路)使用**同一合成接线**,严禁两路漂移(2.6.8 先例)。
- 技能自带的 quick_replies(如破损照片消歧组)是更具体的场景行:**first-wins** 原样保留,不再追加场景组,严禁一屏双胶囊。
- `list_user_orders(shipping_status)`:UNSHIPPED/SHIPPED/DELIVERED,存储值大小写不敏感;**UNSHIPPED = 仍在等待出货**(排除 shipped/delivered/refunded/cancelled——退款/取消单永不出货,算「未发货」会误导用户以为还有包裹在路上;2026-09-12 实弹对 CUST-8801 两笔 REFUNDED 单修正);非法值诚实报错,严禁静默全量;两路查单(商户真单/engine 本地表)走同一纯函数 `_apply_shipping_filter`。
- executor 快路径(`try_match_executor_fast_path`)对「名下订单」类描述与 LLM 路径**同语义**:描述或输入含「未发货/还没发货/尚未发货」时传 `shippingStatus: "UNSHIPPED"`,严禁快路径吞过滤。

## 后果

- **死按钮禁令**:每个快捷按钮背后必须有真实能力兜底——数据诚实铁律(2.6.8)从文本输出延伸到 UI 交互层。
- 卡合成器在购物意图轮多一次品类聚合查询(18 SPU 级,可忽略);查询失败 → 该轮退通用组,**严禁静态假目录兜底**。
- 旧静态四件套整体退役,由场景组取代;前端零改动(协议不变)。
- 遗留(明确不在本期,需用户立项):售后凭证不落工单(`apply_after_sale` 无凭证字段);`queryProductRanking` 数据源错位恒诚实空;onboarding 入口卡(建线程时的欢迎行)维持现状;order_domain 工具出参向 tools-registry §2.1 `{success, data, error}` 形状的整体迁移(存量模式,单改一处会破坏消费方)。

## 验证(2026-09-12,如实)

engine pytest **465 passed**(2.6.13 基线 441 + 新增 24:场景组 13 + 未发货过滤 8 + 快路径 3,零回归,含排行卡契约/订单视图/购物车全域);ruff 干净。实弹(网关重启后):退款反问轮 → 退款场景组四键(无「申请退款」);「查询我未发货的订单」→ 诚实空 + 全量列表佐证(SHIPPED/REFUNDED×2,无一错报未发货);「看看商城有什么商品」→ 6 真品类 chips(各 3 款,18 SPU 对账吻合);点击「潮流鞋靴」chip → 品类过滤浏览 3 款鞋靴;咨询轮 → 通用组四键。
