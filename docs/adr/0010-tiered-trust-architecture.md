# ADR-0010: Data Agent 分层信任架构(T0-T3 通道;「LLM 永不写 SQL」铁律字面废除、精神保留)

日期: 2026-10-07。状态: 已采纳(用户裁决;grilling 会话以「全部规定作废、从零推演哪种最好」收官)。
上位关系: **部分取代** [ADR-0004](0004-semantic-layer-route-and-dual-agent-seam.md) 决议 1 与 [ADR-0005](0005-data-agent-llm-intent-and-growth-loop.md) 决议 1 的「text-to-SQL 不做」字面;[ADR-0006](0006-data-agent-architecture-comparison.md) 的触发器与否定项沿用。spec: `.scratch/data-agent-tiered-trust/spec.md`。

## 背景

1. **课件对照(2026-10-07)**:业界「指标中台/语义层」方法论课件(指标孤岛 → 语义层四层架构 → 声明式 DSL/AST/智能 SQL → 赋能 Agent → 本体/KG)与本仓逐节对照,结论:可信与安全半边(闭集、sql_guard、口径注记、意图层权限收敛)强于课件承诺;缺口集中在 **L2+L3 之间**——`metrics.yaml` 只承载词面/文档(真 SQL 硬编码 `engine.py` 778 行 30+ 分支、join 逐模板手抄、`availableDimensions` 死字段、品类是 9 值正则),即「物理解耦/数据语义层」缺失。
2. **用户翻案两连**:「不按照我之前的规定那种更好」→「所有的规定,从头开始,哪种最好」。从零推演(2026-10、7 表商户域、多租户、中文口语、单部署单库):
   - A 现状闭集管线:安全满分,覆盖天花板 = 登记数,增长靠人力线性堆 —— 2026 年模型能力下属自我设限;
   - B 课件主路线(语义层接地 Text-to-SQL 单通道):GMV 与「华东区利润」走同一条信任管道,要么全信不敢、要么全疑没用;
   - **C 分层信任梯度:唯一同时满足「高频数字可复现可审计(产品需求,非保守)+ 长尾必须能答(增长)+ 错数可发现(诚实)」**;
   - D 全自由 Agent / E 本体+KG:7 表无事实网络,D 拿经营数字冒险,E 先建是负债。
3. **翻案成本核算**:0004 拍板依据(语义层作用域内 ~100% vs text-to-SQL 51-62.5%、生成式静默错数)数字未变;翻案 = 接受长尾通道上该准确率,靠接地 + 守卫 + 盖章兜住,**高频经营数字不降级**。

## 决策

1. **目标架构 = 分层信任梯度**,语义层为地基:
   - **语义层**:`semantic_model.yaml`(实体/关联 join graph/维度/口径版本占位)+ `semantic_compiler.py`(声明 → SQL 编译器)。自研,不引 MetricFlow/Cube——编译产物终归要过自研闸(sql_guard/租户断言/只读 reader),两套编译语义不值。
   - **T0 核验通道**(确定性):认证指标由声明编译出 SQL,零 LLM;现 38 指标从手写模板改为声明编译,不再逐条手写。
   - **T1 组合通道**:LLM 在语义层内自由组合(指标×维度×过滤×时间平移),编译器拼 SQL——长尾覆盖主力。
   - **T2 探索通道**:LLM 接地生成 SQL(schema 卡 + 指标字典为上下文),`sql_guard` 强制闸,输出强制「探索性(非核验口径)」章 + 生成 SQL 折叠展示。
   - **T3 归因**(远期):T1/T2 多步调用 + 综合,归因推理真身;本期不建。
2. **铁律改写**:「LLM 永不写 SQL」→「**LLM 永不在无守卫、无标注的情况下产 SQL**」。字面废除;静默错数防线(响亮失败、诚实空、口径可审计、响亮拒绝)精神全部保留并延伸到新通道。
3. **三档信任章上卡面**:result 帧新增 `trust: verified | composed | explored`;`explored` 帧必带 `generatedSql`(折叠展示,口径可审计)。
4. **迁移纪律**:分族差分对拍(新旧产物 SQL 逐字一致才准切换,销售族 13 指标先行);特殊族**逃生舱**——确实 bespoke 的(核销归因/客户宽表/订单逐笔等)暂留手写 SQL,在模型文件登记债务清单(每条带原因与消灭计划),不强求 100% 声明化。
5. **开闸与灰度**:T1/T2 各挂 env 开关(默认 off);T2 开闸门槛 = eval 集 42→**200**(含 ≥50 条 T2 型长尾问法)+ SQL 质量抽检机制;T2 角色门 = `admin` + `finance_owner` 先行。
6. **死字段清理**:`metrics.yaml` 的 `sqlTemplate`(零消费方实证)与 `availableDimensions`(仅 setdefault 存活)删除;维度声明上收语义模型,品类 9 值正则(`l0_lexicon.py`)退役为模型枚举维度。

## 与 ADR-0004/0005 的关系

- 0004 的**论证**(静默错数、口径不可审计、注入面、权限收敛)在 T0/T1 层全部成立并保留;被取代的只是「LLM 永不写 SQL」的绝对禁令字面。
- 0005 预留的「text-to-SQL 二期演化缝,启用须独立评审 + 非核验口径标注」由本 ADR **正式启用**:本文件即那场独立评审,「非核验口径标注」兑现为 `trust: explored` 章 + 生成 SQL 折叠,另加 0005 未预料的角色门与 eval 门。
- 0006 的「方案一正确位置 = 标注探索通道」预言兑现;其否定项(ANTLR、物化视图、KG、GRPO 主通道)维持。

## 新增不变量

1. 语义模型是**表关联/维度的单一事实源**:编译器、schema 卡、表白名单、T2 接地上下文全部从模型派生;新增表必须先登记模型,安全闸响亮拒绝未登记表(现状纪律平移)。
2. T1 组合查询的角色权限 = 组成指标权限的**交集**(复用 `allowed_metrics_for_role`,不新增权限面)。
3. T2 生成 SQL:**必须**过 `assert_safe_select`(表白名单取模型 merchant_db 实体闭集)、单语句、AST 强制 LIMIT ≤ 50、走只读 reader(3s 超时);engine_db 实体不进 T2 白名单(租户谓词面简化)。
4. 三档章是**机器语义字段**(`trust`),呈现层不得解析口径文案推断信任级(2026-10-03 词面嗅探教训平移)。

## 否决项(从零推演留档)

| 项 | 理由 |
|---|---|
| 维持现状(A) | 覆盖天花板 + 每登记一指标都在加重 engine.py 债务 |
| 单通道接地 Text-to-SQL(B) | 高频数字与长尾探索共用一条信任管道,结构性不可接受 |
| 全自由 Agent(D) | 无守卫自由度,静默错数 + 注入面全量暴露 |
| 本体/知识图谱(E) | 7 表域无事实网络可推理;品类等层级先以声明式维度表兑现 80% 实惠 |
| 引入 MetricFlow/Cube | 编译产物仍须过自研闸,两套语义维护成本 > 收益 |
| ANTLR | 闭集 pydantic + 声明交叉断言已让非法查询不可表示 |

## 后果

- `engine.py` 瘦身:30+ if/elif 模板分支 → 编译器调用 + 逃生舱债务清单(目标:规整族全部迁出,bespoke 族显式登记)。
- 新增能力:任意认证指标 × 声明维度切片、通用时间平移(同环比从 `gmv_mom`/`attribution_*` 孤点模板泛化为算子)。
- 品类从正则常量升格为模型枚举维度后,新增品类改 YAML 不改代码。
- 评测面扩张:现有 42 条 mapping eval 须扩至 200 并新增 T2 型问法族,T2 未达门不开闸(`AI_T2_EXPLORE` 默认 off)。
