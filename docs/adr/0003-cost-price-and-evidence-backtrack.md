# ADR-0003: 成本价数据工程(毛利指标回归)+ 售后凭证会话历史回溯

- 日期: 2026-09-12
- 状态: 设计定案(grill 一轮四问逐项裁决「按照推荐」),随轮实现
- 关联: ADR-0002(凭证落票 / 排行真源 / 热销数据条件禁令——本 ADR 是其二期)

## 背景

ADR-0002 明确留档两个二期项:①成本价数据工程——商户库无成本列,毛利/毛利率指标被整体移除,消歧组缩到 3 键;②售后凭证只带本轮图片,两轮前传的图不回溯。用户裁决一并立项,一个版本交付。

## 决策(用户逐项裁决「按照推荐」)

1. **Q1 成本价双层落库**:`merchant_skus.cost_price`(当前采购进价)+ `merchant_order_items.cost_at_purchase`(成交时进价快照)——毛利 = Σ(数量×成交价 − 数量×快照进价),**精确口径**,与真实电商记账一致;DDL 以 `ADD COLUMN IF NOT EXISTS` 追加进 `_MERCHANT_DDL` 幂等生效,seed 进价按 SKU 编码确定性推导(比例系数调色板,注明演示数据)。
2. **Q2 毛利指标全回归**:`gross_profit` + `margin_rate` 恢复进 METRIC_REGISTRY,统计口径消歧组回 5 键(GMV/销量/净毛利润/毛利率/滞销),`_REMOVED_METRICS` 整体删除;排行条目恢复 `grossProfit`/`marginRate`(前端可选渲染零改动)。
3. **Q3 历史图直查消息表**:售后凭证注入时查本会话 `messages` 中 user 消息的 `image_urls`(engine 与网关共库,threads/orders 先例),newest-first 去重、总上限仍与视觉上限一致;本轮图片优先,本轮无图才回溯。
4. **Q4 一个版本交付**(2.6.16)。

## 后果

- 毛利口径恢复为精确值(成交快照),不再有「估算」角标;指标词汇单一事实源回到 METRIC_REGISTRY(卡合成器消歧组运行时查表取键,不再手抄字面量)。
- 凭证注入点从纯函数变为异步(查询消息表);「本轮无图 + 会话有图」场景闭环。
- 演示数据诚实边界不变:进价系数是 seed 派生规则,排行永远运行时真算。

## 验证(实现后回填,如实)

- engine pytest **492 passed**(2.6.15 基线 484 + 新增 8:毛利快照 2 / 历史回溯 5 / 排行预检谓词 2,含契约翻转改写)、gateway 121 passed、ruff 双服务干净;商户库重播种后 92/92 SKU 与 47/47 明细全带成本快照。
- 实弹(网关重启):「按净毛利润最高的热销商品排行 Top 5」→ 冲锋衣 No.1 毛利 3,507.3 / 毛利率 54.0%;「按毛利率最高查询热销商品排行」→ 速干衬衫 No.1 毛利率 58.0%——不同口径不同冠军,纯真快照数据驱动;带图轮次后无图说退款 → processRefund 审批载荷 args 实弹携带轮 1 的 damaged-jacket.png(历史回溯命中,旧审批行天然对照)。
- 实弹抓出并修复:**毛利排行被两层 LLM 拒答**(triage 分类层 + planner 规划层都把「利润」当后台敏感数据)——triage 判定 1.5 规则前置(`PROFIT_RANKING_RE` 利润词×排行词共现直通 metric_query,确定性规则不触碰 promptfoo LLM 分类基线)+ planner 提示词补经营口径合法性条款;双轴 code-review 再修:三处陈旧注释/文档串对齐 ADR-0003 口径、cost 求和去 COALESCE 0(漏写快照报错可见而非毛利虚高呈精确)、名不符实测试正名、LIMIT 10 注释锚定。
- 判定 1.5 是规则层终局直通的有意扩展(agent-engine §1.3「提议者」原则的边界情形):arbitration_reason="profit_ranking_precheck" 全量落库可审计,与技能快轨同类受控终局。
