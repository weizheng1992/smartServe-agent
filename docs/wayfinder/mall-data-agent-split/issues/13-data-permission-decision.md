# 13: 商户 data agent 数据权限模型拍板

Type: grilling
Status: resolved
Blocked by: 09

## Question

租户内的细粒度数据权限怎么定？（租户间隔离已由 08 号 D4 锁定：business_id 谓词服务端强制注入，非本票问题。）本票管租户之内：

- 商户侧角色模型：商户内是否有老板/运营/客服之分？metric_registry 里已存在但未接线的 permissionTag 三档（sales_viewer / warehouse_operator / finance_owner）——接线还是重设计？
- 行级权限：客服只能看自己名下会话相关数据？运营看全商户？
- 列级/指标级权限：成本、毛利、库存风险等敏感指标是否限档可见（permissionTag 恰好是为此设计的）？
- 权限判定执行位置：工具注册层过滤可见工具 vs SQL 编译层谓词注入（与 08 的租户谓词同一缝）vs 卡片层裁剪；
- 与商户工作台现有 `/api/admin` 鉴权面的关系（复用还是另起）。
- 查询配额与计费：复用 tenant_billing_quotas 的 LLM token 计量即可，还是 SQL 查询单独计量（次数 / EXPLAIN 成本限额）？（fog 毕业至此，09 号缝已定。）

参照：spring-ai-alibaba/DataAgent 仅 API Key 细粒度权限、无多租户行级设计（map Notes），参考价值低，本票自行设计。

## Answer

决议日期 2026-09-17，用户全盘采纳推荐（Q1–Q5）。

### D1 角色模型 = 接线 permissionTag 三档（不重设计）

- **finance_owner = 老板**（全量含敏感）/ **sales_viewer = 运营**（销售、评价、售后，不见成本）/ **warehouse_operator = 仓储**（库存物流面）。
- 员工身份加 role 字段，**默认全员 finance_owner 起步**（现实是多数商户单账号）；角色区分到真实多员工需求出现再激活；角色管理 UI 落 merchant-admin 设置区（19-D4 预留位）。

### D2 指标级权限 = 成本敏感三指标限 finance_owner

- gross_profit（毛利）/ margin_rate（毛利率）/ stock_risk（暴露成本与压货资金）限 finance_owner；GMV / 销量 / 评价 / 退款 / 售后 / 会话全员可见。
- registry 登记新指标**必须带 permissionTag**（18 号评测面作契约检查）。

### D3 行级权限 = v1 不做

全员看全商户行（business_id 隔离已够）；预留编译层谓词缝——将来「客服只看自己会话」在 compile 实体谓词加 staff_id 即可，不动架构。

### D4 执行位置 = 编译层为主 + 卡片层兜底

- resolve/compile 按 role 过滤 metric key 闭集（闭集过滤天然完备）；**反问选项集同步过滤**——低权限用户连「要不要看毛利」的选项都不出现，问不出越权问题。
- 卡片层兜底不渲染越权内容；工具层不做（data agent 无多工具面）。

### D5 配额与计费

- v1 复用 LLM token 计量（tenant_billing_quotas 照记 data agent 的 LLM 调用）；SQL 查询不单独计费。
- 防滥用 = 已有沙箱（EXPLAIN 预算 + 3s 超时 + 50 行）+ **网关层每员工每分钟查询次数限流**（复用滑动窗口基建）；独立查询计费留二期。

## Comments

- 2026-09-18 用户修订：权限配置粒度扩展为**三层 RBAC**——角色 → 可见菜单 + 可见按钮/操作 + 可见指标闭集（如运营可见优惠活动编辑、仓储不见商品模块）；执行仍以服务端为准（编译层过滤 + 网关鉴权），前端菜单/按钮隐藏仅为呈现层。**顶栏增加快捷切换账号**（staff 账号间切换 = 重新走鉴权 + 审计记录；老板可借此预览运营/仓储视角），落 merchant-admin 顶栏账号菜单。
- 2026-09-18 二次修订（spec 发布后追加）：**权限动态配置**——角色→资源映射不写死代码，存 role_permissions 表（resource_type=菜单|按钮|指标，租户隔离，三默认角色种子 + 自定义角色），权限管理页为配置矩阵（保存即生效：服务端权威+缓存失效+审计），护栏=老板「权限管理」不可移除、可恢复默认。已并入 spec 第 3 节；原型权限页改为可交互配置台。
- 2026-09-18 三次修订（用户纠偏）：权限体系定案为标准 **RBAC 三件套**——**菜单管理**（menus 表，目录/菜单/按钮三级，前端路由按配置动态注册，按钮权限点挂菜单下）+ **角色管理**（角色 CRUD + 菜单分配权限树形勾选存 role_menus，指标权限独立分组）+ **员工管理**（staff 表，员工↔角色）；前一版单一「权限配置矩阵」作废。spec 第 3/6 节已改，原型拆为三屏。
- 2026-09-18 用户验收（「可以」）：RBAC 三级树（目录→菜单→按钮权限点）+ 按钮真实生效链路（页面按钮按权限点不渲染）定稿，spec 第 3 节为最终口径。
