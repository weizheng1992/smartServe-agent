# 20: 运营管理（优惠活动）模块规划

Type: grilling
Status: resolved

## Question

2026-09-18 用户新增的模块（目的地重画产物）：后台「运营管理」做各种优惠活动。这是**写操作业务模块**，与 data agent 只读边界分开，需规划：

- 数据模型：优惠活动/券的表设计（商户库现无任何促销表——活动类型：满减/折扣/券？有效期/叠加规则/适用范围 SPU/品类）；
- 与订单链路的关系：下单时如何应用优惠（金额计算改动点在商城 agent 结算链，涉及资金口径——需与 ApprovalGatekeeper 的资金闸关系说清）；
- 商户端 CRUD 界面范围（新建/编辑/停用活动，列表+效果速览）；
- 与 data agent 的衔接：活动效果分析作为新指标族登记（活动 GMV/核销率/拉新），依赖活动数据先落库；
- 写操作边界：后台直接写 or 复用 SPI/审批流；与 08 号「data agent 首版只读」不冲突（这是后台功能不是 agent 动作），但 v1 是否实现、还是 spec 只做规划留二期实现，需拍板。

产出：模块规划决议（数据模型草案 + 界面范围 + 与 data agent/订单链路的边界），进 spec 第④部分。


## Answer

决议日期 2026-09-18，用户采纳推荐（「嗯 继续」按推荐收口）。

### D1 排期 = 规划进 spec、实现排 data agent 之后

优惠活动为**写操作业务模块**，与 data agent 只读边界分开；v1 只做模块规划（数据模型草案 + 边界 + 界面范围），实现列为 data agent 之后的下一批。

### D2 数据模型草案（细节实现期定）

商户库新增两表：`promotions`（活动：类型 = 满减/折扣/券、有效期、叠加规则、适用范围 SPU/品类、状态）+ `promotion_redemptions`（核销记录：活动 × 订单 × 优惠金额）。迁移走 17 号手册式流程（显式 SQL 入仓 + DDL 字符串同步 + CI 护栏）。

### D3 与订单链路的边界

结算时应用优惠属**资金口径改动**（订单金额计算变化），涉及 ApprovalGatekeeper 相关评审与商户 SPI 对账口径——独立实现票处理，不混入 data agent。

### D4 与 data agent 的衔接

活动效果指标族（活动 GMV / 核销率 / 拉新）在活动数据落库后登记进 metric_registry（带 permissionTag），进 L0-L3 全链路。

### D5 界面范围

运营模块 CRUD：活动列表（状态过滤）+ 新建/编辑/停用 + 效果速览卡；写操作走商户后台直接写 + merchant_audit_logs 审计（复用现有审计表）。
