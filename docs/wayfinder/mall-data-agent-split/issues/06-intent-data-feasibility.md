# 06: 意图标注数据可行性评估

Type: research
Status: resolved
Blocked by: 07

## Question

攒出一套可训练的小模型标注数据（意图/口径映射），现实吗？基于 07 号水龙头落码后的导出事实：

- `intent_logs` / `low_confidence_logs` / `badcase_candidates` 各自实际记录的字段、量级（有线上数据看真实量，没有则按管线埋点位置估算流量）；
- 标注方案选项对比：LLM 预标 + 人工复核 / 纯人工 / 现有 promptfoo 评测集（55 条，18 条意图断言）扩充为种子训练集；
- 到「可训」门槛（分落点：意图分类约需多少句、口径映射需多少句）的现实时间线；
- 数据泄漏/评测集污染风险（训练集与评测集怎么隔离）。

产出：数据可行性结论的事实依据与最小标注方案草案，供 11 号决策票引用。

## Answer

### 0. 结论

**可行，但分层：「指标映射头」数周内可训（基本不等日历）；「意图分类头」0.5k 档被动积累约 1-2 个月、主动造数数周；3k 档纯被动不现实，需 LLM 扩写 + 生产流量。** 真正的瓶颈不是行数而是**唯一句覆盖**——dev 库 86% 是评测重跑重复行，且尾类意图唯一句仅 1-3 条。

### 1. 真实量级与积累速度（2026-09-17 经 07 号 CLI 导出复核）

- **intent_logs 1966 行 → 仅 270 个唯一 query**（重复率 86%）。新增唯一句/天：安静日 1-8，峰值日 43/84/62（09-10/12/14，恰为 intent-arbitration 工单测试与 eval 语料撰写期）；两周窗口均值 ≈18 唯一句/天，**持续有机速率估计 5-10/天**。此为 dev 库（测试驱动），不代表生产流量。
- 唯一句×意图分布（长尾断裂）：shopping_guide 80 / cart_manage 40 / order_return 38 / general_query 27 / order_status 21 / order_query 16 / address_manage 12 / consult 12 / refund 8 / order_modify_address 7 / human_escalation 3 / metric_query 3 / address_add 1 / cart_checkout 1 / order_cancel 1。
- 弱标质量：270 唯一句中 259 条 confidence≥0.9（266≥0.8）——但这是**管线自标**（蒸馏天花板：模型学到的是现系统的偏置，含其错误）。
- low_confidence_logs 仅 4 行，`reviewed` 全 false 且无更新方——人审闭环未接线，不能算标注通道。`actual_outcome` 恒空（07 号事实），监督信号只有「预测时点」维度。
- promptfoo 评测集实测：**55 条中 28 条带 expectedIntents**（票面 18 为旧口径），唯一输入 40 个。05 号已定性：这是回归门，不是训练集。

### 2. 「何时够训」时间线（对照 05 号门槛）

| 目标 | 门槛（05 号） | 现状缺口 | 现实时间线 |
|---|---|---|---|
| b 指标映射头 | 150-400 句（20-50/指标） | 日志中 metric_query 仅 3 唯一句，挖矿不够 | **数天-2 周**：sampleQueries 15/指标种子 + LLM 扩写 + 人审即达，日历几乎无关 |
| a1 意图头·最少档 | SetFit 8/类×15=120 | 尾 5 类（1-3 句）需合成补齐 | **现在就能跑通**（玩具基线） |
| a1 意图头·稳妥档 | 32/类×15≈0.5k | 头部类已 8-80 句，总量差 ~230 且尾类断供 | 被动（18/天）≈2-3 周、有机（5-10/天）≈1-1.5 个月；**主动造数（LLM 扩写+人审）数周** |
| a1 意图头·上限档 | 0.5k-3k | 差一个数量级 | 被动 5-16 个月；**必须** LLM 扩写（每种子 5-10 改写）+ 生产流量 |

关键修正：按「行数」看 1966/两周会严重高估——**统计口径必须按唯一句**；且 dev 语料会饱和（重跑不再产生新唯一句）。

### 3. 标注方案对比

| 方案 | 吞吐 | 质量 | 适用 | 判断 |
|---|---|---|---|---|
| LLM 预标+人工复核 | 高（复核 200-500 条/人时，二元确认） | 受蒸馏天花板限制 | 意图头主力：预标=pipeline winner + structured_llm 候选双意见，人只裁分歧/低置信/冲突 | **推荐为主通道** |
| 纯人工 | 低（60-100 条/人时） | 最高（金标） | 只用于：冲突队列定性 + 100-200 条金标种子 | 作金标与仲裁，不做量 |
| 55 条评测集扩充为种子 | — | 人写金标 | 只当 few-shot 锚与扩写种子 | **不推荐入训**（见 §5）；量太小且是唯一回归门 |

### 4. badcase 547 条 intent_conflict 能否当弱标注：**不能直接用，但是最佳辅助标注队列**

- `suggested_class` **恒为 "neutral"**——`intent_signals.py:82` 调用 `record_badcase_signal` 根本不传该参，落的是 `SOURCE_PRIORS` 池分诊先验（`pool.py:29`），**不是意图标签**。直接拿来当分类弱标 = 全部标成 neutral，不可用。
- 但三个事实让它成为高价值队列：① note 携带冲突双方 `层=意图@置信`（二选一假设）；② 504 行=504 唯一线程，**97.6%（492）可经 thread_id 回联 intent_logs 拿到原文**（零原始数据设计下连接径实测通）；③ 去重后实际仅 **71 个唯一难题句**——正是分类头最需要的边界样本。
- 正确用法：每条 = query + {意图A, 意图B, 都不对} 三选一，人工 5-10 秒/条（71 条 ≈ 一小时内清完存量）。**冲突≠错误**（docstring 自认「可能是快轨合法压制」），标签噪声决定必须人审定性、不能无人监督入训。需在 90 天 TTL 内消化（candidate→converted/dismissed 生命周期现成）。

### 5. 训练/评测隔离（防 intentF1 基线污染）

1. **冻结** eval/testCases 55 条为纯门（28 条意图断言，intentF1≥0.8），永不入训、不用于调任何超参。
2. **近重复过滤**：以评测集 40 唯一输入的 embedding 为 blocklist，训练候选 cos≥0.90 直接丢弃、0.80-0.90 人工抽检——防「改写级泄漏」（改写 eval 句入训会虚高 F1，是最现实的污染路径）。
3. **训练池内部再切 10-15% held-out** 作内部 dev：三段路由阈值（05 号 a1）只能在这上面校准，不能蹭评测门。
4. **按句去重入池**：同 query 多次落库只计一条（86% 重复行不去重会扭曲类分布）。
5. **provenance 字段**随行记录（log-mined / conflict-adjudicated / llm-augmented / seed），泄漏可审计可回滚。

### 6. 触发条件建议（供 11 号决策票直接引用）

- **指标映射头（b）：立即启动，不等积累。** 门槛：150-400 句（种子=注册表 sampleQueries + LLM 扩写 + 人审）；验收：内部 held-out 100 句人审准确率超子串匹配基线 + eval metric-disambiguation 场景全绿。
- **意图头（a1）：设数据门槛而非时间门槛——累计唯一标注句 ≥500 且每意图 ≥32**（尾类允许合成补齐但合成占比 ≤50%）；前置：intent_conflict 存量队列（现 71 唯一句）人审消化完毕，并接线 `reviewed` 闭环（现成缝：low_confidence_logs.reviewed 无更新方）。按当前速率预计 1-2 个月达标；**每月 1 日跑 07 号导出统计唯一句/类分布，若连续 2 个月唯一句增速 <300/月，判定被动积累失败，转主动造数**。
- **重训/漂移信号**：intent_conflict 新增唯一句/周 连续 2 周上升 → 概念漂移或新意图进入，触发头重训评估（意图表 9 月已连加两档的先例）。
- **风险注记**：无 actual_outcome 写入方、两表无 TTL——积累期只增不减利好存量，但「预测对不对」无对账维度，弱标正确性只能靠人审队列与评测门兜底；若 11 号批准造数，建议同步补 actual_outcome 最小写入（属增量票，不在本票范围）。
