# PRD —— agent-platform MVP(溯源基线)

> **文档性质声明**:本文件不是原始 kickoff 需求文档,而是 2026-10-31 应工作流结构要求补写的**溯源基线**——把已上线系统的产品边界从既有事实源(`CLAUDE.md`、`docs/adr/`、`.claude/rules/`)压缩而成。产品已远超 MVP 阶段;本文仅锚定「产品是什么、为谁、验收口径是什么」,供 agent 工作流引用。

## 1. 问题与目标用户

电商平台的多方角色各自需要 AI 能力,但信任边界完全不同:消费者要低摩擦答疑;商户员工要自助取数与客服作业;平台运营要管控与观测。一个多租户平台统一供给,租户间数据物理/逻辑隔离。

## 2. 用户故事(已上线能力)

1. 作为**消费者**,我可以与 AI 客服对话(流式回复、富卡片、图片上传),敏感操作转人工坐席接管,断线后恢复不丢上下文(ADR-0013)。
2. 作为**消费者**,我可以在商户商城浏览、加购、下单、查单,游客身份与注册身份严格隔断(U2 游客律)。
3. 作为**商户员工**,我可以用自然语言查询经营数据(销售/商品/客户 41 指标),得到卡片化结果,且确信查询被租户边界与只读守卫约束(ADR-0010)。
4. 作为**商户坐席**,我可以在工作台认领会话、查看订单面板、向客户推送卡片。
5. 作为**平台运营**,我可以管理租户、技能、画像、guardrails、RAG 文档、计费、日志,并审批 AI 发起的高危动作(HITL)。

## 3. 范围边界

- **范围内**:四前端 + 网关 + 引擎 + 本体层;多租户隔离;HITL;数据分析 Agent;记忆与 RAG;人工接管。
- **范围外**:多实例部署编排;外置工作流引擎(Temporal 已退役,ADR-0007);任何自由 SQL 入口;跨租户数据访问。

## 4. 验收口径

- 行为契约:137 条 HTTP 端点 + SSE 线格式 + socket.io 事件,由 pytest 契约套件钉死,新增路由同批补契约。
- 质量契约:promptfoo 评测金字塔(意图 564 锚点、unified、planner、persona 四册 + pin/compare 门禁 + judge 校准 ≥80%)。
- 诚实契约:缺值不编造(数据诚实律),真实数据优先于演示数据。
