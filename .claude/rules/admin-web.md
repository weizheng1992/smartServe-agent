# Admin 后台管理系统规范 (Admin Web)

本工作区负责面向运营与风控人员的 HITL（Human-in-the-Loop 人机协同）审核工作台、客户画像分析、会话历史追溯以及运维指标大盘。

## 1. 核心架构与功能模块

### 1.1 HITL 待审工作台 (`PendingApprovals.tsx`)

- **待审卡片交互**：按动作类型（退款审批、收货地址变更、高危售后干预等）差异化展示风控原因与风险等级。
- **决策操作三部曲**：
  - **同意 (Approve)**：通过审批，触发底层 Transactional Outbox 恢复执行挂起的工作流任务。
  - **驳回 (Reject)**：拒绝申请，通知 Agent 向用户解释拒绝原因并提供合规建议。
  - **人工接管 (Takeover)**：暂停 AI 智能体托管，将当前会话转入人工客服接待通道。
- **触发原因诊断 (Trigger Diagnosis)**：自动高亮触发安全审批门禁的具体风控规则（如：_“退款金额超过商户 $50.00 免审阈值”_）。

### 1.2 360° 全景上下文抽屉 (`ApprovalContextDrawer.tsx`)

引入自 `@agent-all/ui` 的全景抽屉式审查容器，包含三个核心视图：

1. **对话与执行上下文 Tab (Context & Dialog)**：
   - 完整回放触发审批前的用户对话历史。
   - 展示智能体当前的任务规划拓扑图快照与执行节点状态。
2. **客户画像与偏好 Tab (User & Persona)**：
   - 解析客户底层真实身份（用户 ID、邮箱、会员层级）。
   - 展示全局物理画像（`scope: 'global'`，如鞋码、过敏史）与商户专属偏好（`scope: 'tenant'`，如常购品类、优惠券偏好）。
3. **历史购买轨迹 Tab (Purchase History)**：
   - 异步拉取 `/api/chat/orders?userId=...` 数据。
   - 展示规范化收货地址（收件人、联系电话、省市区与详细地址门牌）及关联的商品购买明细。

### 1.3 历史审计台与运维指标 (`HistoricalAudits.tsx`, `Metrics.tsx`, `PersonaAudit.tsx`)

- **历史审计**：查看已完成/已驳回审批的历史决策日志与操作人快照。
- **大盘指标**：聚合展示自动决议比例（Autopilot Resolution Ratio）、LLM Token 消耗成本估算及平均响应延迟。
- **画像管理**：对系统自动提取的客户长周期事实（Facts）进行人工核准或修正。

## 2. 开发准则与最佳实践

1. **多租户权限边界**：所有待审单拉取、审批提交与画像查询必须携带 `businessId` 租户上下文，严禁跨租户越权。
2. **乐观更新与幂等控制**：
   - 审批决策提交后必须触发 React Query 局部乐观更新，并使当前审批列表缓存失效。
   - 防止由于网络延迟导致的重复点击提交。
3. **空数据防崩策略**：
   - 用户画像、收货地址或历史订单为空时，必须提供优雅的中文占位展示（如“暂无历史订单”、“未登记详细地址”）。
4. **架构解耦**：
   - 复杂的异步请求与本地状态管理收敛在 `apps/admin/app/home/hooks/`。
   - 抽屉及卡片展示逻辑复用 `@agent-all/ui` 共享组件。
